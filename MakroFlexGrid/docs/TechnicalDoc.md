# Technical Documentation: MaKroFlexGrid

`MaKroFlexGrid` представляет собой высокопроизводительную реализацию WPF-таблицы с поддержкой сложной визуальной структуры и механизмов синхронизации. Данный документ описывает внутреннее устройство контрола и принципы его работы.

## 🏗 Архитектурный паттерн

Контрол использует гибридный подход, сочетающий классический WPF (Custom Control) и элементы паттерна **Presenter-ViewModel**.

### Основные компоненты:
- **CustomDataGrid (Core)**: Центральный узел управления. Наследуется от `DataGrid`. Хранит общие свойства (цвета, отступы) и координирует работу презентеров.
- **Presenters (Visual Layer)**: Специализированные `FrameworkElement` (`ColumnHeadersPresenter`, `UnifiedRowsPresenter`, `BottomPanelPresenter`), которые отвечают за отрисовку конкретных зон.
- **ViewModels (State Layer)**: Объекты (`RowViewModel`, `CellViewModel`, `BottomPanelViewModel`), которые хранят состояние элементов и уведомляют визуальный слой об изменениях через `INotifyPropertyChanged`.

## ⚙️ Ключевые механизмы

### 1. Синхронизация горизонтального скролла
Одной из главных сложностей контрола является синхронизация трех независимых зон: **Left Frozen**, **Scrollable Center** и **Right Frozen**.

- **ScrollManager**: Централизованный сервис, который отслеживает изменение смещения (`HorizontalOffset`).
- **ScrollBehavior**: Прикрепленное свойство (`Attached Property`), которое используется в XAML-шаблонах. Оно применяет `NegativeValueConverter` к текущему смещению, фактически сдвигая контент внутри `StackPanel` в противоположную сторону от скролла, создавая эффект "скольжения" данных.
- **Механика**: Когда `CustomDataGrid` меняет `HorizontalOffset`, все подписанные `ViewModel` обновляют свои свойства, что вызывает перерисовку через биндинги в шаблонах.

### 2. Виртуализация и жизненный цикл строк
Для обеспечения высокой производительности при тысячах строк используется `UnifiedRowsItemsControl` с `VirtualizingStackPanel`.

- **Recycling**: Контейнеры строк (`RowContainer`) переиспользуются. При переиспользовании вызываетс�� метод `Clear()`, который отписывает старую `RowViewModel` от событий, чтобы избежать утечек памяти.
- **RowViewModel $\rightarrow$ CellViewModel**: Каждая строка создает набор `CellViewModel` для каждой видимой колонки. Это позволяет каждой ячейке независимо управлять своим шаблоном и значением.

### 3. Управление памятью и слабые ссылки
В контроле активно используются механизмы предотвращения утечек памяти, связанных с событиями `DependencyProperty` в WPF:
- **WeakDependencyPropertyListener**: Обертка, позволяющая слушать изменения свойств `DataGridColumn` без создания сильных ссылок, которые могли бы помешать сборщику мусора (GC) удалить колонку или сам грид.
- **WeakActionHelper**: Используется для регистрации коллбэков, которые не должны удерживать объекты в памяти.

## 🛠 Гайд по модификации и расширению

### Добавление нового типа фильтра
1.  **Создать класс фильтра**: Наследоваться от `ColumnFilterBase`. Реализовать логику проверки условия в методе, который будет вызываться `FilterService`.
2.  **Создать UI-контрол**: Разработать XAML-контрол для выбора параметров фильтрации (например, `CustomRangeFilterControl`).
3.  **Обновить `FilterUIFactory`**: Добавить условие в метод `CreateFilterControl`, чтобы фабрика знала, какой UI-контрол создавать для данного типа данных или фильтра.

### Добавление нового агрегата в нижнюю панель
1.  **Добавить значение в `AggregateType`**: В файле `Headers/AggregateType.cs` добавить новый тип (например, `Median`).
2.  **Реализовать расчет**: В `BottomPanelPresenter.cs` в методе `CalculateNumericAggregate` добавить логику вычисления нового значения на основе списка объектов `items` и `sortMemberPath`.

### Изменение визуальной структуры
Все основные стили находятся в `Themes/`. 
- Для изменения внешнего вида ячеек редактируйте `Themes/RowTemplates/DefaultCellTemplate.xaml`.
- Для изменения поведения заголовков (цвета при Drag&Drop, иконки) используйте `Themes/Headers.xaml`.
